# 云眸 · 热气球标志袋无人机判读系统

热气球比赛中，裁判需要测量每位选手投下的标志袋中心到目标十字的距离。本系统用无人机航拍照片，
经控制点校正为统一比例尺正射图，自动检出各种颜色的标志袋、编号牌与飘带，按**颜色 + 编号**认出选手，
在 **Web Worker** 中完成识别与量距，用 **Canvas** 叠加正射底图和每个袋子到十字的连线，最后按赛事规则计分排名、发布成绩。

> 纯前端 TypeScript + React + Vite，照片与数据全部在本地浏览器处理，不上传服务器。

## 快速开始

```bash
npm install
npm run dev        # 打开终端提示的地址（固定 5180 端口）
```

生产构建与本地预览：

```bash
npm run build      # tsc --noEmit 类型检查 + vite 打包（Worker 独立分包）
npm run preview
```

### 厘米级精度自检（Node，无需浏览器）

```bash
npm run validate
```

该脚本在 Node 中跑与浏览器**完全相同**的核心链路（程序化样例 → DLT 控制点解算 → 透视校正 →
连通域/OCR/测距 → 对比裁判真值），三个光线/地形场景的实测结果：

| 样例场景 | 判出 | OCR 编号 | 最大距离误差 | 平均误差 | 检测+测距耗时(Node) |
| --- | --- | --- | --- | --- | --- |
| 清晨玉米垄（长影 / 只露飘带） | **40/40** | 40 | **1.01 cm** | 0.30 cm | ~2.5 s |
| 正午混作田（泥地 / 水沟） | **40/40** | 40 | **1.03 cm** | 0.43 cm | ~3.2 s |
| 傍晚葡萄园（暗光 / 三对近色相邻袋） | **40/40** | 40 | **1.31 cm** | 0.45 cm | ~3.9 s |

浏览器端到端实测（Playwright/Chromium，1600×1000）：40/40 判出、40 个编号 OCR 命中、
含 Worker 消息往返的整轮约 **3.8–3.9 s**（限额 60 s），裁判复核最大偏差 **1.0 cm，40/40 ≤ 3 cm**，
控制台无错误。

## 四个页面（对应赛事流程）

1. **航拍导入**：三张程序化生成的赛区样例卡片——清晨玉米垄、正午泥地水沟、傍晚葡萄园近色连袋；
   也支持点击/拖拽上传自己的航拍 JPG/PNG。右侧为 40 名选手名册与注册袋色。
2. **控制点校正**：Canvas 显示原片与 6 个可拖拽棋盘控制点、目标十字；右表可改地面坐标（米）/启停/增删。
   用 **DLT + 归一化 + Jacobi 特征分解**最小二乘解算单应矩阵，给出重投影 RMS，再由 Worker 透视重采样成
   70 px/m（≈1.43 cm/px）的正射图。
3. **标志袋识别**：Worker 跑白色编号牌分割 → 连通域几何筛选 → 5×7 点阵整码模板匹配 OCR →
   注册颜色复核 → 未命中编号再按注册色追踪飘带锚点。Canvas 叠加目标十字、目标区圆、
   **每个袋子到十字的量距连线**、袋色圆点与编号。支持点选、拖动中心微调、下拉改派编号、删除、手动补点，
   并列出裁判复核值与厘米偏差、Worker 各阶段耗时。
4. **成绩发布**：领奖台 + 完整排名表。距离升序、越近越前、同厘米并列；目标区（默认 18 m，可调）外记最低分。
   支持规则调整、导出带 BOM 的 CSV / JSON、浏览器打印、一键发布公告。

## 针对题目难点的设计

- **两垄之间只露飘带**：这类袋子不画袋体，只画沿垄沟铺设、锚点端带编号段的锥形飘带；
  编号段与普通编号牌走同一套 OCR，中心即飘带锚点（= 袋中心真值）。另有按注册色做的飘带主轴/宽端锚点追踪兜底。
- **近色相邻袋按编号拆分**：`05/06`、`17/18`、`29/30` 是三对刻意安排的近色袋，中心相距约 0.8 m、
  颜色掩膜会粘连，但各自有独立白色编号牌，OCR 直接按编号区分身份，绝不靠颜色猜人。
- **被飘带遮住一半**：飘带真实搭过袋身；所有编号牌在所有袋子/飘带之后统一最上层绘制，保证号码始终可读
  （OCR 的墨迹判定还会排除高饱和彩色飘带，兼容真实照片里号码被彩色物扫过的情况）。
- **厘米级吻合**：中心由 OCR 模板最佳原点反推牌面中心（与牌宽/padding 无关），避免连通域被杂色撑宽导致的中心偏移；
  再经统一比例尺换算距离。
- **40 人 < 1 分钟**：全图仅做少量线性扫描 + 连通域，OCR 只对几何合格的候选牌打分；整轮浏览器实测约 4 s。
- **几种样例图自己做**：`src/sample/scene.ts` 用带种子的软件光栅器逐像素生成农田垄、泥地、水沟、
  控制点、目标十字、袋体/飘带/编号牌与清晨/正午/傍晚光照，浏览器与 Node 像素完全一致，无任何外部图片资源。

## 坐标与计分约定

- 地面坐标单位为米，原点为目标十字；x 向右、y 向下（与正射图像素同向）。
- 正射比例尺 `70 px/m`，原点固定在输出图中心 `(1599.5, 1199.5)`（偶数宽高下的中心像素中心）。
- 距离 `d = hypot(gx, gy) * 100` cm。
- 计分（规则可在成绩页调整）：
  - 区内：`score = round(1000 * max(0, 1 - d_m / R))`；
  - 区外 `d_m > R`：记最低分 `0`；
  - 排名始终按距离升序，区外排在区内之后，同距离（厘米）记并列名次。

## 上传自有照片

上传后控制点表会预填 6 个粗略位置：在「控制点校正」页把橙色棋盘拖到真实地面控制点，
并在右侧填入实测 X/Y（米），至少 4 个点即可解算校正。真实照片中的编号牌字体/尺寸若与内置 5×7 模板差异较大，
可用识别页的「下拉改派编号 / 拖动中心 / 手动补点」完成人工复核——量距与排名会即时重算。

## 目录结构

```
src/
  lib/        类型、DLT 单应矩阵、软件光栅器、点阵字体、颜色、计分、Canvas 工具
  sample/     程序化样例场景（地形/光线/40 个落点与裁判真值）
  detect/     连通域、OCR、检测+量距核心（纯 TS，可在 Node/Worker 运行）
  workers/    judge.worker.ts（生成样例 / 校正 warp / 识别测距 / 重算）+ 客户端
  state/      全局 store
  components/ JudgeCanvas 量距叠加画布
  pages/      导入 / 控制点校正 / 识别 / 成绩发布
scripts/
  validate.ts 端到端厘米级自检（npm run validate）
```

## 技术说明

- 检测核心不依赖 DOM，输入输出都是普通 `Raster { width, height, data: Uint8ClampedArray }`，
  因此同一份代码既能在浏览器 Worker 跑，也能被 Node + tsx 直接验证。
- 生产构建已验证：`npm run build` 通过，Worker 被 Vite 拆为独立 chunk。
